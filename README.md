## 現状

`assets/SD.png` の SD キャラを、**写真を一切使わず** JavaScript だけで描画している。
`shapes.js` は座標と色だけのデータで、実行時に画像は一切読み込まない。

```
tools/analyze.py   画像を解析して shapes.js を生成する (開発時のみ実行)
tools/strokes.py   線画を中心線 + 線幅のストロークに変換する
shapes.js          自動生成。パスの d 属性・色・グラデーション・部位ラベル
main.js            shapes.js から SVG を組み立てて描画する
index.html         表示用
```

現在 **2484 パーツ** (面 456 + 線 2026 + 口 2)。各パーツには `data-label`
(hair / skin / iris / eyeLine / hoodie / legs / shoes / earInner) が付いていて、
部位単位でアニメーションさせるための下地になっている。

## 解析パイプライン

1. **背景除去** — 画像の外周から白のまま繋がっている領域だけを背景とみなす。
   単純な白判定だと髪やパーカーの白まで消える。
2. **減色** — メディアンで階調をならし、CIE Lab 空間で k-means。色度 a\*b\* を
   強調してあるのは、面積の小さい瞳の紫が髪の薄紫クラスタに吸収されるのを防ぐため。
3. **パーツ分割** — 色クラスタを連結成分に分け、`面積 x 重要度` で採否を決める。
   重要度は彩度と暗さから出す。まつ毛のように小さくても効くものを残すための重み。
4. **輪郭** — marching squares → 閉曲線 RDP → Catmull-Rom → 3 次ベジェ。
5. **完全分割** — 採用しなかった画素を同色クラスタの最近傍パーツに吸収させる。
   前景に隙間が残らないので、パーツの継ぎ目から下地が透けない。
6. **グラデーション** — パーツごとに色を位置の線形関数として最小二乗で近似し、
   `linearGradient` にする。単色で塗ると階調が段々になる。
7. **残差 ROI** — ここまでの結果を塗り直した画像と原画を Lab で比べ、誤差の
   大きい領域だけを細かい設定で再解析する。顔や口の位置を決め打ちしなくても、
   どこが再現できていないかを画像自身が教えてくれる。
8. **線画** — 残差を見ると、面はほぼ再現できていて残りはほとんど線画だった。
   原画は「線画 + 塗り」なので、black-hat で細い線だけを取り出して最前面へ重ねる。
   OKOJO ロゴや髪の流れが戻るのはこの段階。

## 線を「面」ではなく「ストローク」で描く理由

線を塗りつぶしの面として描くと、細いマスクの輪郭が往復して棘だらけになる。
それを平滑化で消そうとすると、細い線ごと消える — **「棘を消す」と「細い線を残す」
が同じつまみになってしまう**。実際、マスクのぼかしを sigma 1.1 まで上げた時点で
顎の輪郭線と OKOJO ロゴの「J」が消えた。

`tools/strokes.py` は線を中心線と線幅に分解する。

1. Zhang-Suen 細線化で 1px の中心線にする
2. 端点から辿ってポリラインにする。**分岐点では進行方向に最も近い枝へ進む** —
   機械的に切ると、髪のように何度も交差する絵では 1 本の流れが断片に割れる。
   直進する枝が無ければそこで切る (無理に曲がると別の線に飛び移る)。
   また分岐点は `visited` で占有しない。占有すると先に通った線が交差点を取り、
   他の線がそこで途切れる。
3. 線幅は距離変換の値の 2 倍 (中心線上の値 = 中心から縁までの距離)

こうすると平滑化の強さと線の細さが独立するので、棘だけを消せる。
変形させたときも線幅が追従するため、部位ごとのアニメーションにも向く。

## アニメーション

`main.js` が同じラベルのパーツを `<g>` にまとめ直し、グループごと transform する。
現在動いているのは目・口・アホ毛。

- **まばたき** — 2〜6 秒のランダム間隔。22% の確率で二度続けて瞬きする。
  等間隔だと機械的に見える。閉じるより開くほうを緩やかにしている
- **口** — 呼吸に合わせて縦に開閉。原画の口は 5px しかないので動きは控えめ
- **アホ毛** — 周期の違う 2 つの正弦波を重ねて、根元を軸に回す
- **耳** — ときどき両耳そろってぴくっと動く。左右は鏡写しに振る
  (同じ向きに回すと頭ごと傾いたように見える)。軸は耳の根元

## 表情差分

原画は一つの表情しか持たない。差分は「元の目を隠して別の形を出す」という
足し引きで作る。画面下のボタンで切り替わる。

| | 中身 |
|---|---|
| ふつう | 原画のまま。まばたきする |
| 笑顔 | 目を隠し、上に凸の弧を出す。まばたきは止める |
| びっくり | 目を 1.18 倍に |

笑い目の弧は原画に無い形だが、**線の色はまつ毛から借りている**。形は足しても、
色は絵から取ったほうが浮かない。

表示の切り替えは `display` 属性で行う。`style.display` を空にするだけでは、
`build()` が隠すときに付けた `display="none"` 属性が残って出てこない。

### 部位の決め方

色から推測した `guess_label` は面の分類には足りるが、部位としては当てにならない
(白目が "hair" に分類されるなど)。動かす部位は瞳の位置を基準に取り直していて、
その閾値は**画面上でパーツに色を塗り、目視で確かめて決めた**。

目のグループは「領域」で決めている。瞳の中央値を中心に固定サイズの矩形を取り、
**描画範囲ごとその中に収まるパーツ**だけを集める。

重心で判定してはいけない。目の上を通り過ぎるだけの長い髪のストロークが入り、
グループの外形が顔ごと覆う大きさに化ける (実際 361x513 まで膨らんだ)。
描画範囲で見れば、白目もまつ毛も入り、通過する線は入らない。

白目を取りこぼさないことも重要で、まつ毛と瞳は暗いので色で拾えるが、**白目は肌より
明るいので色では拾えない**。置き去りにすると目を閉じたときそこだけ白い穴が残る。
領域で取ればこれも解決する。取り込むと重なり順が崩れるので `depth` で並べ直す。

## レイヤー構造

前景を完全分割していたので、**各画素はどれか 1 つのパーツにしか属していなかった**。
瞳の中心を貫いて数えても要素は 1 枚きりで、目を動かせばそこは空洞になる。
まばたきが成立していたのは、目のグループごと潰していて穴が露出しなかっただけ。

いまは顔の下地を目・口より奥に敷いている。

```
顔の下地      目・口の下にある肌。動かしても空洞にならない
  口内        原画には無い。喋らせるために足したもの
    唇        原画の 3x2px の点 2 つ
  目          白目 → 瞳 → まつ毛
```

顔の下地には二つ手当てが要った。ひとつは、**額が前髪で完全に隠れていて肌として
写らない**こと。肌の色から取れる「顔」は目より下しかなく (実測で目の中心が上端の
5px 上に外れる)、上方向へ伸ばして目を覆わせている。ここは前髪の下に隠れるので
多少大きくても見た目には出ない。

もうひとつは穴の色で、目や口があった場所は**最も近い肌の画素から色を取る**。
平均色で塗ると顔の陰影と合わず、そこだけ一枚浮く。

口内は原画に無い。口は閉じた状態の点 2 つきりなのだから当然で、喋らせるなら
足すしかない。その点 2 つを上唇とみなし、口内はその下に、上端を軸にして開く。
中心を軸にすると唇より上にも広がって顔にめり込む。

### まだ手をつけていない部位

- **前髪と後ろ髪の分離** — 髪は 898 パーツあるが分かれていない。前髪を目の上に
  重なる独立レイヤーにしないと、顔を動かしたときの前後関係が正しくならない
- 耳・眉毛・腕もまだ部位になっていない。眉は前髪にほぼ隠れていて、
  独立したパーツとして取れるかどうかから確かめる必要がある

### 残差の数値について

`analyze.py` は各段階で平均 Lab 距離を出すが、これは**面の**再現度の指標。
線画を重ねると数値はむしろ悪化する — 線は面積が小さく、1px ずれるだけで
両側に誤差が出るため。見た目の良し悪しはこの数値では決まらない。
